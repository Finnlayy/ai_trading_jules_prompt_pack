## 1. Neue Backend-API-Endpunkte (`app/api/academy.py`)
Bevor das Frontend mit den Backtesting- und Optimierungsfunktionen interagieren kann, müssen die entsprechenden Endpunkte im FastAPI-Router registriert werden.

* **`POST /api/academy/policy/backtest`**:
  * **Payload**:
    ```json
    {
      "engine": "backtrader" | "vectorbt",
      "timeframe": "1m" | "5m" | "15m",
      "bars": 1000,
      "params": {
        "target_scout_index": 0,
        "min_reward": 0.0,
        "min_accuracy": 0.5
      }
    }
    ```
  * **Response**: Unified Metrics (Sharpe Ratio, Drawdown, Calmar Ratio, PnL, equity curve).
* **`POST /api/academy/policy/optimize`**:
  * **Payload**:
    ```json
    {
      "method": "differential_evolution" | "minimize" | "grid_search",
      "initial_params": { "reward_weights": [...], "scout_thresholds": [...] },
      "objective_weights": { "sharpe": 1.0, "drawdown": 1.0, "calmar": 1.0 }
    }
    ```
  * **Response**: Optimierte Gewichte und Schwellenwerte.
* **`GET /api/academy/policy/backtest/plots`**:
  * **Query-Params**: Typ des Plots (z. B. `equity`, `correlation`, `distribution`, `kpi`).
  * **Response**: Base64-kodiertes PNG (`data:image/png;base64,...`), das direkt in ein React-`<img>`-Tag eingebunden werden kann. Dies erspart komplexe JavaScript-Zeichenlogik im Frontend und nutzt die vollen Möglichkeiten von **matplotlib** und **seaborn**.

### 1. Swarm Orchestration Flow
When a webhook signal (M8 payload) enters `process_signal()` in [orchestrator.py](file:///g:/Downloads_Sortiert_2026-05-20/ai_trading_jules_prompt_pack/app/api/orchestrator.py):

2. **Context Delivery**: The orchestrator builds a clean, secret-free JSON context containing the market state, active strategy parameters, current paper balances, open positions, and historical performance.
3. **Scout & Gem Reviews**: The selected agents run in parallel (using `GemNativeReviewService` / `KimiSwarmService`). Each agent outputs a structured JSON report specifying a recommendation (`PROCEED_TO_SIMULATION`, `REJECT`, or `HUMAN_REVIEW`), a confidence score, and reasoning.
4. **Weighted Synthesis**: The orchestrator aggregates the individual reviews by weighting each agent's vote using live accuracy metrics from the **Confidence Registry**. If a critical veto agent (like `risk_kernel` or `execution_watchdog`) votes `REJECT` with high confidence, the orchestrator triggers a veto rejection.

---

### 2. The Flow of Authority (Advisory vs. Deterministic)
While the AI layer coordinates the agents to form a decision:
* **The AI Swarm is advisory**: The AI swarm cannot execute trades or bypass rules on its own.
* **Deterministic Risk Engine is Authoritative**: The generated `SignalReview` is passed into the deterministic Risk Engine ([risk_engine.py](file:///g:/Downloads_Sortiert_2026-05-20/ai_trading_jules_prompt_pack/app/services/risk_engine.py)).
* **Hard Gates**: The Risk Engine checks `_gate_ai_conflict()`. If the AI layer voted to `REJECT`, requested `HUMAN_REVIEW`, or if the swarm's confidence fell below the War Room safety threshold (`WAR_ROOM_AI_MIN_CONFIDENCE`), the Risk Engine enforces a hard deterministic gate to block execution.

---

### 3. Swarm Memory & Academy (The Second Brain)
To prevent memory loss across stateless LLM calls:
* **Second Brain**: Performance metrics, open positions, and agent accuracy records are compiled into [wiki/second_brain.md](file:///g:/Downloads_Sortiert_2026-05-20/ai_trading_jules_prompt_pack/wiki/second_brain.md).
* **Live Updates**: Whenever a trade outcome is finalized, or an agent registry update occurs, dynamic hooks call `update_second_brain()`.
* **Academy Integration**: The Meta-Orchestrator tracks the agents' career registry. When an agent's accuracy decays below the threshold, it triggers a mandatory training drill in the Academy ([training_drills.py](file:///g:/Downloads_Sortiert_2026-05-20/ai_trading_jules_prompt_pack/app/services/training_drills.py)) to calibrate and upgrade their prompt performance.
